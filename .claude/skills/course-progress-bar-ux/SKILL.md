# Course Progress Bar UX — 课程进度条上下文/概览双模式逻辑

## 核心概念

进度条面对两种**互斥**的场景，它们的判断逻辑完全不同，必须在代码层面完全隔离：

| 模式 | 触发条件 | 状态判断依据 | 百分比显示 |
|------|---------|-------------|-----------|
| **上下文模式** | 当前页面 URL 匹配到课程中的某个视频 | **位置** — 当前视频之前的默认已完成，当前=当前，之后=未开始 | 已完成=真实 watched%，当前=真实 watched%，未开始=0% |
| **概览模式** | 当前页面 URL 不匹配任何课程视频 | **实际观看比例** — >50% 已完成，≤50% 未开始 | >50% 显示真实比例，≤50% 显示 0% |

## 铁律

1. **两个分支代码完全隔离**
   - 不能共享 `getVideoProgress()` 或 `getVideoStatus()` 这类统一函数
   - 每个分支内联自己的计算逻辑
   - 分支判定：`currentIdx >= 0` → 上下文模式，`currentIdx === -1` → 概览模式

2. **Bar 视觉填充 ≠ Tooltip 信息**
   - Bar 可以简化（上下文模式按位置变色，概览模式按阈值变色）
   - Tooltip 必须忠实反映数据，不能硬编码 100% 或 0%
   - "已完成"是状态标签，不代表 watched 一定是 100%

3. **上下文模式没有"进行中"**
   - 按位置判断只有三种状态：已完成 / 当前 / 未开始
   - 不要试图用概览模式的阈值逻辑污染上下文模式

## 错误案例

| 错误操作 | 实际后果 | 正确做法 |
|---------|---------|---------|
| 两个分支共用 `getVideoDisplayProgress()` 函数 | 无关页面看了 39% 显示 0%，因为函数内部有 50% 阈值 | 每个分支内联自己的百分比计算 |
| 试图统一状态枚举为"未开始/进行中/已完成" | 上下文模式出现了不存在的"进行中"状态，逻辑混乱 | 上下文模式只有三种状态，概览模式只有两种，分别内联 |
| 上下文模式把"已完成"视频的 tooltip 硬编码为 100% | 用户 hover 时发现 tooltip 与实际 watched 数据不符 | tooltip 显示真实 watched 比例，只有 bar 填充按位置逻辑 |
| 把概览模式的 50% 阈值带到上下文模式的当前视频 | 当前视频看了 30%，tooltip 却显示 0% 和"未开始" | 当前视频的 tooltip 始终显示真实比例 |

## 正确代码结构示例

```javascript
// === 分支 A：上下文模式（课程视频内部）===
if (currentIdx >= 0) {
  if (videoIndex < currentIdx) {
    status = '已完成';
    percent = duration > 0 ? Math.round((watched / duration) * 100) : 0;
  } else if (videoIndex === currentIdx) {
    status = '当前';
    percent = duration > 0 ? Math.round((watched / duration) * 100) : 0;
  } else {
    status = '未开始';
    percent = 0;
  }
}

// === 分支 B：概览模式（无关页面）===
else {
  const ratio = duration > 0 ? watched / duration : 0;
  status = ratio > 0.5 ? '已完成' : '未开始';
  percent = ratio > 0.5 ? Math.round(ratio * 100) : 0;
}
```

## 通用 UX 原则

- **进度条是承诺**：用户看到绿色填充，预期的是"这部分我走过了"
- **Tooltip 是真相**：hover 时应该暴露底层真实数据，不做二次加工
- **上下文模式是「导航」**：帮用户知道自己在课程的哪个位置
- **概览模式是「仪表盘」**：帮用户知道各课程的完成度
