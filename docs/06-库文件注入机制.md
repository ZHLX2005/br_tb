## 注入方式概述

Chrome 扩展有多种方式向网页注入资源：

| 方式 | 使用场景 | 优点 | 缺点 |
|------|----------|------|------|
| **content_scripts** | 页面加载时注入 | 自动化、可靠 | 所有页面都会注入 |
| **动态注入** | 按需加载 | 节省资源 | 需要手动触发 |
| **web_accessible_resources** | 允许页面访问 | 灵活性高 | 安全风险 |

本插件使用 **content_scripts** 方式自动注入 Marked.js 和 KaTeX 库。

## manifest.json 配置

### 配置结构

**文件位置**: [`manifest.json:21-27`](../manifest.json#L21-L27)

```json
{
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": [
        "content/lib/katex.min.js",     # 1️⃣ KaTeX (269KB)
        "content/lib/marked.min.js",     # 2️⃣ Marked.js (35KB)
        "content/content.js",            # 3️⃣ 业务代码
        "content/content-ocr.js"         # 4️⃣ OCR 模块
      ],
      "css": [
        "content/content.css",           # 样式1
        "content/content-ocr.css",       # 样式2
        "content/lib/katex.min.css"      # KaTeX 样式 (23KB)
      ]
    }
  ]
}
```

### 配置项说明

| 属性 | 值 | 说明 |
|------|-----|------|
| `matches` | `["<all_urls>"]` | 匹配所有 URL |
| `js` | 数组 | JavaScript 文件列表 |
| `css` | 数组 | CSS 文件列表 |

**注意事项**:
- `js` 和 `css` 数组中的**顺序很重要**
- 先注入的脚本定义的全局变量，后续脚本可直接访问
- CSS 后注入的样式会覆盖先注入的（相同选择器时）

## JavaScript 注入机制

### 1. 注入时机

```
页面导航开始
     │
     ▼
┌─────────────────────────┐
│ 浏览器解析 HTML          │
└─────────────────────────┘
     │
     ▼
┌─────────────────────────┐
│  Content Scripts 注入   │ ← 阻塞页面渲染
│ (DOMContentLoaded 之前) │
└─────────────────────────┘
     │
     ▼
┌─────────────────────────┐
│ 页面脚本执行            │
└─────────────────────────┘
     │
     ▼
 DOMContentLoaded 事件
```

**关键点**:
- Content scripts 在 `DOMContentLoaded` **之前**注入
- 注入过程会**短暂阻塞**页面渲染（15-30ms）
- 所有脚本按顺序执行

### 2. 执行顺序详解

```javascript
// ========== 第 1 步：注入 KaTeX ==========
// 文件：content/lib/katex.min.js (269KB)

// 全局变量：window.katex
// 内容：KaTeX 核心库 + 字体数据 + 渲染引擎
// 影响：后续脚本可直接使用 katex.renderToString()

// ========== 第 2 步：注入 Marked.js ==========
// 文件：content/lib/marked.min.js (35KB)

// 全局变量：window.marked
// 内容：Markdown 解析器
// 影响：后续脚本可直接使用 marked.parse()

// ========== 第 3 步：注入业务代码 ==========
// 文件：content/content.js

// 可访问：
// - window.katex ✓
// - window.marked ✓
// - DOM API ✓

// 不可访问：
// - 页面的 JavaScript 变量 ✗

// ========== 第 4 步：注入 OCR 模块 ==========
// 文件：content/content-ocr.js

// 可访问：
// - window.katex ✓
// - window.marked ✓
// - content.js 中定义的全局变量 ✓
```

### 3. 全局作用域验证

在 content.js 中可以直接访问注入的库：

```javascript
// 检查库是否加载
console.log(typeof marked);      // "object"
console.log(typeof katex);       // "object"

// 使用库函数
marked.parse('# Hello');        // ✓ 正常工作
katex.renderToString('x^2');    // ✓ 正常工作
```

### 4. 运行时环境隔离

Content scripts 运行在**隔离的世界**（Isolated World）中：

```javascript
// Content script 中
window.katex     // ✓ 可以访问（注入的库）
window.pageVar   // ✗ 无法访问（页面变量）
document.body    // ✓ 可以访问（DOM）

// 页面的脚本中
window.katex     // ✗ 无法访问（content script 的变量）
window.pageVar   // ✓ 可以访问（页面自己的变量）
document.body    // ✓ 可以访问（共享 DOM）
```

**隔离机制**:
- JavaScript 全局对象隔离
- DOM 共享
- CSS 共享

## CSS 注入机制

### 1. 注入顺序

```
页面 <head>
     │
     ▼
┌─────────────────────────┐
│ 1. content.css          │ ← 基础样式
└─────────────────────────┘
     │
     ▼
┌─────────────────────────┐
│ 2. content-ocr.css      │ ← OCR 样式
└─────────────────────────┘
     │
     ▼
┌─────────────────────────┐
│ 3. katex.min.css        │ ← KaTeX 公式样式
└─────────────────────────┘
```

### 2. 样式优先级

CSS 级联规则（Cascade Order）:

```
优先级从高到低：
1. !important 声明
2. 行内样式（style attribute）
3. ID 选择器 (#id)
4. 类选择器 (.class)
5. 元素选择器 (div, p)
6. 通配符选择器 (*)

相同时，后注入的优先级更高
```

**示例**:

```css
/* content.css - 先注入 */
.panel { color: blue; }

/* content-ocr.css - 后注入 */
.panel { color: red; }  /* 最终颜色：red ✓ */
```

### 3. KaTeX 样式

KaTeX 需要 CSS 来正确显示公式：

```css
/* katex.min.css (23KB) 包含：*/

/* 公式容器 */
.katex-display {
  display: flex;
  margin: 1em 0;
  justify-content: center;
}

/* 行内公式 */
.katex {
  font-size: 1.1em;
  white-space: nowrap;
}

/* 数学字体 */
.katex-mathml { ... }
.katex-html { ... }
```

**为什么 KaTeX CSS 要最后注入？**
- 确保公式样式不被覆盖
- 公式样式优先级应该最高
- 避免页面样式干扰公式显示

### 4. 样式隔离问题

**问题**: Content script 注入的 CSS 可能影响页面样式

**示例**:
```css
/* content.css */
.panel { background: white; }
```

如果页面也有 `.panel` 类，会被覆盖。

**解决方案**:
1. **使用特定 ID 选择器**（推荐）
   ```css
   #selection-result-panel { ... }
   ```

2. **使用嵌套选择器**
   ```css
   #selection-result-panel .panel-header { ... }
   ```

3. **使用 Shadow DOM**（高级）
   ```javascript
   const shadow = element.attachShadow({ mode: 'open' });
   shadow.innerHTML = `<style>/* 完全隔离的样式 */</style>`;
   ```

## 全局作用域管理

### 1. 变量命名冲突

**问题**: 多个 content scripts 共享全局作用域

```javascript
// content.js
let markedConfigured = false;

// content-ocr.js
let ocrMarkedConfigured = false;  // 使用前缀避免冲突
```

### 2. 命名约定

**方案 1: 前缀约定**（本项目使用）

```javascript
// 划词模块
function renderMarkdown() { }
function renderLatex() { }

// OCR 模块
function ocrRenderMarkdown() { }
function ocrRenderLatex() { }
```

**方案 2: IIFE 隔离**

```javascript
// 立即执行函数表达式
(function() {
  let markedConfigured = false;  // 私有变量

  function renderMarkdown() { ... }

  // 只暴露需要的函数
  window.SelectionRenderer = {
    render: renderMarkdown
  };
})();
```

**方案 3: ES6 模块**（推荐）

```javascript
// manifest.json
{
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["content/lib/katex.min.js"],
      "type": "module"  // 启用模块模式
    }
  ]
}
```

### 3. 库的全局变量

**Marked.js**:
```javascript
// 注入后创建
window.marked = {
  parse: (markdown) => { ... },
  setOptions: (options) => { ... }
};
```

**KaTeX**:
```javascript
// 注入后创建
window.katex = {
  renderToString: (latex, options) => { ... },
  __parse: (latex) => { ... }  // 内部解析器
};
```

## 最佳实践

### 1. 库文件组织

**推荐结构**:
```
content/
├── lib/
│   ├── katex.min.js       # 第三方库
│   ├── marked.min.js
│   └── katex.min.css
├── utils/
│   └── markdown-renderer.js  # 共享渲染逻辑
├── content.js            # 业务代码
└── content-ocr.js
```

### 2. 注入优化

**问题**: 所有页面都加载 327KB 库文件，即使不需要

**优化方案: 动态注入**

```javascript
// 1. manifest.json 中移除库注入
{
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["content/content.js"],  // 只注入业务代码
      "css": ["content/content.css"]
    }
  ],
  "web_accessible_resources": [
    {
      "resources": ["content/lib/*.js", "content/lib/*.css"],
      "matches": ["<all_urls>"]
    }
  ]
}

// 2. 在 content.js 中按需加载
async function loadMarked() {
  if (window.marked) return window.marked;

  const script = document.createElement('script');
  script.src = chrome.runtime.getURL('content/lib/marked.min.js');
  document.head.appendChild(script);

  return new Promise(resolve => {
    script.onload = () => resolve(window.marked);
  });
}

// 3. 使用时才加载
async function renderMarkdown(text) {
  const marked = await loadMarked();  // 首次使用时加载
  return marked.parse(text);
}
```

**收益**:
- 90% 不使用划词的页面零注入
- 首次使用时延迟 50-100ms（可接受）
- 整体性能提升显著

### 3. 体积优化

**Minified vs Original**:

| 文件 | 原始大小 | Minified | Gzip |
|------|---------|----------|------|
| marked.js | ~150KB | 35KB | ~12KB |
| katex.js | ~850KB | 269KB | ~75KB |
| katex.css | ~60KB | 23KB | ~6KB |

**优化建议**:
1. ✅ 使用 minified 版本
2. ✅ 启用 Gzip 压缩
3. ✅ 考虑 Tree-shaking（如果使用模块）
4. ✅ CDN 替代（如果允许网络访问）

### 4. 版本管理

**推荐做法**:

```javascript
// 库版本常量
const LIB_VERSIONS = {
  marked: '9.1.2',
  katex: '0.16.8'
};

// 版本检查
function checkLibVersion() {
  if (typeof marked === 'undefined') {
    console.error('Marked.js not loaded');
    return false;
  }

  console.log(`Marked.js v${LIB_VERSIONS.marked} loaded`);
  return true;
}

// 初始化时检查
checkLibVersion();
```

## 常见问题

### Q1: 为什么 content scripts 可以访问注入的库？

**A**: Content scripts 注入的文件都运行在同一个**隔离的 JavaScript 世界**中，共享全局作用域。

### Q2: 页面脚本可以访问 Marked.js 吗？

**A**: 不可以。Content scripts 和页面脚本的 JavaScript 环境是隔离的，但 DOM 共享。

### Q3: 如何避免样式冲突？

**A**:
1. 使用 ID 选择器而非类选择器
2. 使用嵌套选择器
3. 考虑 Shadow DOM（完全隔离）

### Q4: 可以动态加载库吗？

**A**: 可以，使用 `chrome.runtime.getURL()` + 动态创建 `<script>` 标签。

### Q5: 为什么 KaTeX CSS 要最后注入？

**A**: 公式样式优先级应该最高，避免被其他样式覆盖。

## 总结

### 关键要点

1. **注入顺序**: KaTeX → Marked.js → 业务代码 → OCR 模块
2. **作用域共享**: Content scripts 共享全局作用域，需要避免命名冲突
3. **环境隔离**: Content scripts 与页面脚本 JS 隔离，DOM 共享
4. **CSS 优先级**: 后注入的样式优先级更高
5. **性能优化**: 考虑动态注入减少不必要加载
